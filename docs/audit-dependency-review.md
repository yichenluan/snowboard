# 教学清单的依赖分层

2026-10-15。本次修改清单的失效范围，不增加人工审读、画面观察或教学通过记录。

## 动画指纹

此前每条动画引用都包含全部 `lesson-player/` 与 `prototype/` 源文件的摘要。任意独立动作变更都会让所有动画观察过期。现在采用 `runtime-imports-with-task-routing-v1`：

1. 从课内播放器入口、样式、桥接和当前任务实现开始，追踪实际本地运行时 `import` / `export from`；忽略纯类型导入，保留共享辅助文件的递归依赖。
2. 只在已知分派文件 `main.tsx`、`motion.ts`、`diagnostics.tsx` 中，按配置选择任务及可启用的诊断图。独立任务文件内部新增共享导入会自动进入依赖。未识别的新导入默认保留，不默默省略。
3. 图表依赖也参与指纹。例如腿长图直接使用 `pressure-advanced.ts` 的辅助计算，因此它并非只属于该模块自己的动作课。左右前脚、两向转换及界面开放的同任务对照仍属于同一文件依赖范围。
4. 共享人体、雪板表面、场景、播放器控制和样式发生变化，所有依赖引用仍会失效。独立专家刻滑模块变化不再使前刃基础动画失效；独立 `/3d/` 原型按自身入口闭包登记。

生成 JSON 的 `dependencyFiles` 列出每个对象实际采用的文件集合，动画对象另列 `dependencyPolicy`。任务、类型索引使用所含引用的依赖并集。全站播放器功能入口仍使用完整动画文件集合，因为它代表整个播放器能力。

这是一套按当前分派契约计算的静态依赖，不是程序任意路径的形式化证明。修改任务类型、支持判断、跨任务对照或图表挂载条件时，须一起核对脚本的分派映射与回归测试。共享分派文件改动仍会使全体相关动画失效；不通过局部哈希来掩盖分派变化。第三方包升级、构建工具改变和设备差异仍需另行验证，本次不宣称覆盖它们。

算法版本纳入动画指纹。旧观察使用原来的指纹，生成器不会改写、迁移或补齐它们。历史记录若与当前指纹不同，继续显示 `stale`，原状态、范围和证据保留。这意味着本轮可能先产生更多过期记录，收益是后续独立任务修改更少误伤无关引用。

## 页面与路线登记

`guide-state.js` 纳入页面、功能与课程的 UI 输入。它改变路线翻页、筛选、自检合并或个人数据处理时，相应页面证据会过期。

- `navigation-route:<routeId>`：六条学习路线独立登记，校验稳定 ID、标题、简介、进入条件、非空且不重复的有效课程引用。
- `curriculum:<stableId>`：原有 16 项阶段标准继续保留其语义身份和稳定 ID，仅作为补充参考；不会把六条新路线套用到旧专家阶段的审读记录上。
- 自检由实际页面的 `SnowGuide.checks` 合并 `lesson.checks` 和仍有差异的 `drill.success`。练习条目指纹包含有效自检结果；去掉重复字段不再产生“缺少 success”的误报。

新登记对象默认未审读、未核验。字段完整和引用正确不等于雪友能执行，也不等于动画教学正确。
