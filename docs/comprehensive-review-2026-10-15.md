**1　先修正两处内容口径**

**枢转定义过宽，造成前后课程自相矛盾。** [术语定义](../content.json#L20208)将 Pivot 定义为“雪板长轴在雪面平面内改变朝向的运动”；[技术地图](../content.json#L18754)也使用“板头板尾在雪面上改变朝向”。但纯刻滑同样沿弧改变航向，后续刻滑课又要求不依靠枢转，雪友很容易误读为“刻滑时板轴不能转向”。

建议改写为：“在本手册采用的 CASI 语境中，枢转指通过身体旋转输入，调节雪板相对行进方向的朝向与转向角。沿刻滑弧线自然发生的航向改变，本身不能据此判断为主动枢转。”同时区分板轴朝向、移动方向、两者夹角和主动控制；不要进一步简化为“只要有枢转就一定搓雪”。增加一个板轴与移动方向的俯视对照，比再加一段关节口令更有效。依据为 [CASI Reference Guide](https://members.casi-acms.com/documents/Ref_Guide.pdf) PDF 第 47、60–61 页，本轮通过本地同源原书核对。

**SBINZ 来源说明已与现行网页不符。** [S11 摘要](../content.json#L18206)和[后刃高度课的引用](../content.json#L3979)称当前网页没有列出屈曲、伸展两种换刃。实际 [SBINZ Level Three 页面](https://www.nzsia.org/snowboard/snowboard-level-three-new/)在 Versatility Riding Assessment 中明确要求展示 flexed/extended edge change。

应同步更正两处，写清这是 Versatility 的要求，不能把它误归到网页其他小节；仍保留“考核要求不能直接推出所有雪友统一的高低姿态”的边界。来源核验记录应绑定实际支持结论的小节及日期。

**2　组织结构应按学习决策组织**

现有 13 个模块适合查资料，但不宜直接承担所有人的学习顺序。进阶路线又被渲染为连续的 01–16 阶段：低位 duck、专家刻滑排在普通小回转之前，回收与反脚靠后。正文虽然解释了两条主线、选修和并行，视觉编号仍容易让人以为必须依次完成。证据见 [路线渲染](../app.js#L145)。

建议保留现有模块作为“全部内容”，首页主要提供三个入口：“按当前能力继续”“解决一个滑行问题”“查技术资料”。学习路径组织为：

| 路径 | 内容与进入条件 | 避免形成的误解 |
| --- | --- | --- |
| 共同基础 | 双刃控速与退出、连续圆弯、可调整的站姿、可靠的双向转换 | 看完关节知识就等于具备滑行能力 |
| 刻滑主线 | 浅刻滑与完整弧线 → 两侧支撑和释放 → 不同条件下保持结果 → 专家任务复核 | 摸雪、最低姿态就是刻滑等级 |
| 小回转主线 | 连续搓雪圆弯 → 逐步缩弯 → 计划走廊与完整滑段 → 专家任务复核 | 短弯必然要求一种固定回收方式 |
| 可选风格 | 已可靠刻滑基础上的 duck 低姿态、摸雪等应用 | 所有人进专家课程前必须先练低位 |
| 并行能力 | 反脚、装备适配、体能及任务相关的单项练习 | 必须学完高级刻滑才能开始反脚 |

**翻页必须遵守正在学习的路线。** 当前[上一点和下一点](../app.js#L94)使用全局 `data.lessons[index±1]`。数组中可出现“练习设计 → duck → 专家短弯”，专家短弯复核后又直接接专家刻滑，与当前模块或能力路线无关。线上亦实际复现了跨模块翻页。

建议显式保存进入课程的路线上下文，按该路线翻页；直接深链进入时，按当前模块顺序，并显示“下一课：具体标题”。不改变课程稳定 ID，避免破坏收藏、讨论和已有深链。

**专项筛选有确定遗漏。** [筛选逻辑](../app.js#L32)只接受 `level === '专项'`，线上因此仅显示 2 课，漏掉 10 门 Expert 课及“专项进阶”的 duck 课。应把难度、学习分支、内容类型分开存储，筛选依据稳定字段，展示文字可独立修改。

**4　文字要从“论述正确”进一步做到“可以执行”**

**同一学习结果重复出现。** 113 课中有 101 课的 `checks` 与 `drill.success` 完全相同，页面仍分别展示。多个感知课也重复安排小幅侧滑、单弯到连弯：例如靴舌、踝、髋和胸部的前刃提示，都可能服务同一个核心任务。

建议只维护一份通过标准；雪前显示当前 1–2 条观察点，雪后展开完整标准。保留不同提示的价值，但呈现为“遇到此症状时选一种”，验证有效后撤掉提示，而不是积累更多需要同时注意的身体部位。

**专家课有些动作要求仍过于抽象。** 例如“只小幅改变腿长调节的启动点或持续时间”“两向各做一次小幅时机调整”，没有说明普通学习者如何根据当前现象选取第一项调整。其技术边界是谨慎的，但执行决策留给了用户。

每课至少配一张默认实验卡：适用现象 → 所需前置 → 哪个阶段改变什么 → 哪些条件保持不变 → 比较什么结果 → 失败后退到哪里。某个问题需要现场辨别时就明确写出，不要给所有人统一的“提早收腿”处方。

例如针对“只有降低高度后才卡旧刃”，可先用当前已有内容重组为：在熟悉且已可靠的刻滑条件做正常高度、稍低、恢复正常三段；本趟只观察两向释放与下一弧入口；若问题仅低位出现，取消降低并恢复余量；若正常高度也出现，转回释放与弧线诊断。这个实验能决定下一步，不必先猜压力大小。

**建议统一课程首屏模板：**“本课解决什么”“开始前需要什么”“这一趟只做什么”“看哪两个结果”“何时退回”。原理、替代提示和出处随后展开。较长专家课仍可保留完整解释，但不要求用户先阅读全部才能练。

引用边界尽量留在证据层。例如[平板支撑剂量](../content.json#L13098)出现“不是癌症预康复处方”，这是来源适用人群的说明，应移到引用卡；执行剂量只保留本站起始量、动作质量和停止条件。课程正文出现的 `s20-rails` 等内部 ID，也应转换为可点击的课程标题。

**5　三维演示应围绕一个观察问题组织**

现有同源路线图、关节标注、前脚切换、两刃方向、阶段定位和参考对照有保留价值。骨长、装备连接与任务约束比单纯追求视觉夸张更重要。当前抽查没有提供足够证据，支持把已查看动作整体判为错误。

主要改进如下：

1. **默认先看完整任务，再看当课差别。** 播放器当前默认“分解”，同时展示多个控制项和 20、21、25 或 37 个阶段。可用“完整动作”“本课重点”“自由观察”三层组织；第一次先以正常示意速度看完整任务，再跳到关键事件。正常示意速度也不应标为真实专家滑速。
2. **当前提示始终紧邻画面。** [实现](../lesson-player/main.tsx#L200)已将专家提示放在阶段列表前，普通任务却放在长列表后。统一到前方，详细阶段列表折叠或限高，避免为找“现在看哪里”滚动整个播放器。
3. **差异小，先改比较方式。** 同进度、固定相机的并排或叠影，配一个局部高亮；内倾与成角看骨盆胸廓关系，转向看板轴和移动方向，回收看跨侧与腿长时序。不要把所有关节幅度放大来增加戏剧性。
4. **抽象对照的边界放在对照名称附近。** 同路线、同板角的屈腿偏晚演示只隔离身体组织，不能证明这种姿态仍能产生同样的真实线路。现有解释已基本说明这一点，建议进一步将“只比较腿长时序”设为对照的短标签，减少用户只看动画而跳过长说明的误读。
5. **低位演示按实际层级命名。** duck 示例相对正常参考，抽样前刃中段骨盆高度低约 4.6 cm，后刃约 11.8 cm，入口差别更小。这只是模型差值，不是人体目标。建议在播放器直接写“正常 → 略低 → 恢复”，并说明当前展示低位进阶的第一步；无需为匹配标题改成极端深蹲。
6. **建立少量真人与三维配对。** 结构化 `videoStudy` 当前只在两门专家复核课。优先为双向换刃、连续圆弯、浅刻滑、回收、duck、扭板六类核心任务提供有授权的真人完整动作，配同一个观察问题的三维片段。真人负责展示完整任务与真实结果，三维负责解释难以看清的关系。新增一个漂亮模型不能替代这一步。

验证演示时，应按实际事件取样：旧刃释放前、近平板、新刃建立、前后刃弧内和出口，而非只截五个均匀时间点。前后刃和两种前脚方向需要分别审，固定关节角度不宜写成所有人的目标。

**6　移动端和复盘应服务雪上使用**

**窄屏将整列动画和评论放到了目标、前置条件之前。** [样式](../styles.css#L5)在 1100 px 以下将动画列提前，760 px 以下继续保持相同顺序；该列包括播放器、说明、GitHub 评论及通用提示。390×844 视口中，浅刻滑课播放器约在文档纵坐标 817 px，评论约 2595 px，目标约 2847 px，练习约 4992 px。页面没有横向溢出，但到达任务的阅读距离明显过长；顶部跳转按钮只能部分缓解。

建议顺序为：目标与适用条件 → 本趟任务卡 → 简版动画 → 练习与自检 → 详细原理和证据 → 评论。再提供一个雪上精简视图，只保留任务、两项检查、退阶条件和记录入口。评论功能保留并移到完整内容之后。

**本课复盘没有使用已经存在的重点字段。** 例如[专家短弯调压课](../content.json#L16560)只指定 5 项 `assessmentCriteriaIds`，但 [mount 调用](../app.js#L96)没传该列表，[复盘组件](../assessment.js#L58)始终渲染协议全部条目。结果是短弯课每次 11 项，刻滑课每次 12 项，包含本次可能完全不练的 duck。

建议默认显示本课的 3–5 个重点，可展开全表；专项复核页显示全量。增加“本次不适用”，与“未观察”分开；隐藏条目的原有数据必须保留，不因换课或切换重点被清除。记录仍按协议和记录 ID 隔离。

复盘最先回答三件事：本趟改了什么，哪一个可观察结果改变了，下一趟继续、退阶还是换一个假设。完整指标用于周期复核，不必变成每趟的长问卷。当前没有自动算 CASI 分数、也不把自查等同资格认证，这一点应保留。[CASI Level 4](https://casi-acms.com/courses/level-4-instructor/)是涵盖滑行、教学及教练培训等要求的认证，网站上的两项滑行专项不能代表全部资格。

| 内容字段与展示分离 | 专项筛选依赖 `level` 展示字符串；重点复盘字段未进入 UI | 为难度、分支、课型和前置建立稳定字段，校验实际使用关系 |

| 审阅失效范围过粗 | [清单脚本](../scripts/inventory-teaching.mjs#L40)把所有动画文件加入每一条引用的指纹 | 区分共享人体约束、任务模块、渲染层、页面层的依赖；共享变化仍全量复核，独立任务只使相依证据失效 |
| 个人数据保存 | [save](../app.js#L26)每次序列化整份 guide，复盘输入每次触发保存 | 只持久保存个人数据、schema 和版本；内容从内嵌常量读取，迁移保护旧个人记录。这是维护与写入成本改进，未据此断言已出现性能卡顿 |
| 源码可读性 | `app.js`、样式和部分组件把大量逻辑压成单行 | 格式化源文件，拆分页面渲染、路线选择、存储与记录职责；构建时继续压缩 |

历史的 stale 状态表示证据与当前输入不再严格对应，不代表相同数量的教学错误。不能通过刷新指纹把状态改绿；依赖拆分的作用是让真正需要重看的内容更明确。

**8　建议实施次序与验收**

| 批次 | 范围 | 完成判据 |
| --- | --- | --- |
| 第一批　修口径和错误入口 | Pivot 与 S11 两处口径；专项筛选；按路线翻页；复盘重点字段 | 相同术语跨课一致；专项包含预期课程；从路线进入后上下课不跳到无关分支；换课不丢记录 |
| 第二批　缩短学习流程 | 首页分支、目标与任务前置、移动端顺序、自检去重、默认实验卡 | 首个课程内容区就能看到任务与前置；单课默认不要求填写全量复盘；同一验收语句只维护一份 |
| 第三批　优化观看 | 先完整后局部、提示置顶、关键事件、同相位对照、按任务选择视角 | 用户能指出本课差别及出现阶段；两种前脚方向和双向换刃无标签错配；未扩大关节动作来制造差别 |
| 第四批　补真实学习证据 | 核心真人配对、普通雪友试用、来源与动画分层复核 | 记录首次误解、任务执行、撤提示后的结果及复测；技术结论由相应证据支持 |

建议先选 6 门代表课作为完整样板：前刃基础、后刃基础、双向换刃、连续小回转、浅刻滑、专家调压。用统一模板验证后再铺开 113 课，减少全站重写后再次返工。

可用少量符合前置条件的雪友做形成性试用：读完首屏后，让其用自己的话复述“这趟做什么、看什么、失败退哪里”，再在适当现场指导下验证执行与撤提示后的表现。此类小样本用于发现学习障碍，不用于声称课程有效率或教学认证。

**深度交互**

“把所有知识和所有动作补完整”与“帮助普通雪友更快学会”不是同一个目标。现有内容已足够多，继续增加技术点，可能使用户更难选择、同时背负更多身体口令。下一阶段更值得验证的目标是：一个人能否选对当前任务，按要求练习，观察结果，再做出正确的下一步决定。

建议把网站明确定位为“已有基本滑行能力者的训练手册与技术参考”。对不具备双刃控速、退出及基本雪道判断的用户，保留清楚的进入边界；不必为了覆盖所有人而再扩成一套庞大的零基础、竞技、自由式和野雪百科。

因此最优先投入应是任务选择、观看提示、练习反馈和真人校验。保留已有的技术严谨性，将它放在用户需要时能找到的位置；首页和雪上视图集中帮助用户完成一次清楚、可验证的练习。
